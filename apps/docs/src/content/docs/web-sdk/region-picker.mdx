---
title: RegionPicker
description: The headless widget behind a region picker's trigger and list.
---

The headless widget behind a region picker's trigger and list. It reads its rows from a
[`RegionList`](/web-sdk/region-list/) and holds the open state, the keyboard cursor, and the
selected option. Every change emits a [`RegionPickerState`](#regionpickerstate) snapshot. Bound to a
[`PhoneInput`](/web-sdk/phone-input/), the phone owns the selected region and the picker follows
it. No emit fires at construction; read the bootstrap with [`getState`](#getstate).
[`attachRegionPicker`](#attachregionpicker) wires a trigger, a popup, and a listbox to it.

## createRegionPicker

```ts
function createRegionPicker<T = undefined>(options: RegionPickerOptions<T>): RegionPicker<T>;
```

```ts
const regions = createRegionList({ prioritize: ['US', 'CA', 'GB'] });
const picker = createRegionPicker({ regions, phone });

picker.open();
picker.search('can');
picker.getState().active; // 'CA'
picker.select('CA'); // phone.setRegion('CA')
picker.close();
```

## RegionPickerOptions

| Field     | Type            | Meaning                                                                                               |
| --------- | --------------- | ----------------------------------------------------------------------------------------------------- |
| `regions` | `RegionList<T>` | The list the picker reads its rows from. The picker never destroys it.                                |
| `phone`   | `PhoneInput`    | The phone input that owns the selected region. See [Bound to a phone input](#bound-to-a-phone-input). |

## RegionPickerState

```ts
type RegionPickerState<T = undefined> = {
  readonly open: boolean;
  readonly selected: RegionOption<T> | null;
  readonly active: RegionCode | null;
  readonly options: readonly RegionOption<T>[];
  readonly searchQuery: string;
};
```

`selected` is `null` until a region is selected. It is the option from the list's base set, the same
object the list renders. It follows [`localize`](/web-sdk/region-list/#localize) and
[`refresh`](/web-sdk/region-list/#refresh). `active` is the row under the keyboard cursor and is
`null` while closed. `options` and `searchQuery` mirror the list's state.

## Bound to a phone input

With a `phone`, the phone input is the single source of the selected region. The picker subscribes
to it and takes `selected` from the phone's resolved region, keeping the last region while the phone
reports `null`. [`select`](#select) hands the region to
[`setRegion`](/web-sdk/phone-input/#setregion) instead of storing it. Undo on the phone therefore
moves the picker as well. A `select` that round-trips through the phone emits once.

The picker writes only its search query to `regions`. Filters stay where they are set. Give the
list and the phone the same `regionFilter` and `numberTypeFilter` when the rows must match what the
phone accepts.

## Members

### subscribe

```ts
subscribe(listener: RegionPickerListener<T>): () => void;
```

Subscribes to state changes. Returns an unsubscribe function.
`RegionPickerListener<T>` is `(state: RegionPickerState<T>) => void`.

### getState

```ts
getState(): RegionPickerState<T>;
```

The current state, without subscribing.

### open

```ts
open(): void;
```

Shows the list with an empty query and the cursor on the selected row, or on the first row when
the selection is filtered out. A no-op while open.

### close

```ts
close(): void;
```

Hides the list and clears the cursor. A no-op while closed.

### toggle

```ts
toggle(): void;
```

`open` while closed, `close` while open.

### search

```ts
search(query: string): void;
```

Updates the query on `regions`. A new row set moves the cursor to the first row, which lets Enter
pick the top match. An unchanged query is a no-op.

### setActive

```ts
setActive(region: RegionCode | null): void;
```

Puts the cursor on a row, or clears it with `null`. A region outside `options` clears it.

### moveActive

```ts
moveActive(step: number): void;
```

Moves the cursor by `step` rows, wrapping at both ends. Without a cursor, a positive step starts at
the first row and a negative one at the last.

### select

```ts
select(region: RegionCode): void;
```

Selects a region. Bound to a phone, the phone receives the region; on its own, the picker keeps
it. A region the list does not know changes nothing. Closing the list after a pick stays with the
caller.

### destroy

```ts
destroy(): void;
```

Unsubscribes from `regions` and the phone and clears all listeners. Idempotent. The list and the
phone stay alive. Destroy the picker before or together with the phone; a `select` after the phone
is gone has nothing to write to.

## attachRegionPicker

```ts
function attachRegionPicker<T = undefined>(options: AttachRegionPickerOptions<T>): RegionPickerAttachment;
```

Wires a trigger, a popup, and a listbox to a picker. Events flow in and state flows out. The
adapter builds no elements of its own. Rows come from `renderOption` and the empty element from
`renderEmpty`. The trigger's content, the styling, and the popup's position stay with the caller.

```html
<button class="picker-trigger"><span class="picker-code"></span></button>
<div class="picker-menu" hidden>
  <input type="text" placeholder="Search" />
  <ul></ul>
</div>
<input type="tel" class="phone" />
```

```ts
const code = document.querySelector<HTMLElement>('.picker-code')!;

const attachment = attachRegionPicker({
  picker,
  trigger: document.querySelector<HTMLButtonElement>('.picker-trigger')!,
  popup: document.querySelector<HTMLElement>('.picker-menu')!,
  search: document.querySelector<HTMLInputElement>('.picker-menu input')!,
  listbox: document.querySelector<HTMLElement>('.picker-menu ul')!,
  renderOption: (option) => {
    const row = document.createElement('li');
    row.textContent = `${option.displayName} +${option.callingCode}`;
    return row;
  },
  renderTrigger: (selected) => {
    code.textContent = selected === null ? '' : `+${selected.callingCode}`;
  },
  returnFocusTo: document.querySelector<HTMLInputElement>('.phone')!,
});
```

| Field           | Type                                          | Meaning                                                                                       |
| --------------- | --------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `picker`        | `RegionPicker<T>`                             | The picker to wire.                                                                           |
| `trigger`       | `HTMLButtonElement`                           | The button that opens the list. It gets `type="button"` when the attribute is absent.         |
| `popup`         | `HTMLElement`                                 | Holds the search field and the listbox. Shown and hidden through `hidden`. May live anywhere. |
| `listbox`       | `HTMLElement`                                 | Receives the rows.                                                                            |
| `search`        | `HTMLInputElement`                            | The search field. Without it the trigger carries the combobox role.                           |
| `renderOption`  | `(option: RegionOption<T>) => HTMLElement`    | Builds a row. The adapter adds `role`, `id`, `data-region`, `aria-selected`, `data-active`.   |
| `renderTrigger` | `(selected: RegionOption<T> \| null) => void` | Called on attach and on every change of the selection.                                        |
| `renderEmpty`   | `() => HTMLElement`                           | Builds the element shown while the rows are empty.                                            |
| `returnFocusTo` | `HTMLElement`                                 | Focused after a pick. The trigger by default.                                                 |
| `autoFocus`     | `boolean`                                     | Focus the search field when the list opens. `true` by default.                                |

What the adapter wires:

- A click on the trigger toggles the list. A closing click returns focus to the trigger when focus
  was inside the popup. On the trigger and on the search field, `ArrowDown` and `ArrowUp` open a
  closed list and move the cursor in an open one. `Enter` picks the cursor's row, moves focus to
  `returnFocusTo`, and closes. While the list is open, `Enter` never submits a surrounding form.
  `Escape` returns focus to the trigger and closes. Keys pressed during IME composition are
  ignored.
- Typing in the search field searches. A query set on the picker is written back to the field.
- A click on a row picks it. A moving pointer moves the cursor. A list scrolling under a resting
  pointer leaves the cursor in place. The cursor scrolls into view within the listbox on open and
  on keyboard moves.
- A press outside the trigger and the popup closes the list, as does focus leaving them. The press
  is seen in the capture phase, before any handler on the pressed element.
- On the trigger, `aria-haspopup`, `aria-controls`, and `aria-expanded`. On the search field, or
  on the trigger without one, `role="combobox"`, `aria-controls`, `aria-expanded`, and
  `aria-activedescendant`, plus `aria-autocomplete="list"` on the search field. On the list,
  `role="listbox"` and `tabindex="-1"`, which keeps a scrollable list out of the tab order. On
  every row, `role="option"`, an id, `data-region`, `aria-selected` for the selected region, and
  `data-active` for the cursor. Ids are unique per attachment.
- Rows are cached per option object and reused across searches. A localized list yields new rows.

The trigger's accessible name stays with the caller, as does its content. A stylesheet that sets
`display` on the popup must keep `[hidden]` hidden. Give the list and the phone the same filters
when the rows must match what the phone accepts.

### destroy

```ts
destroy(): void;
```

Removes every listener, the document-level one included, and unsubscribes from the picker.
Idempotent. The picker stays alive, as do the rendered elements and their attributes. Call it when
the elements leave the page.
